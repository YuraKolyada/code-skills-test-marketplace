# Безпека (на основі OWASP Top 10 і ASVS)

Порушення з цього списку — блокери: не залишай їх у коді, навіть якщо людина не просила про безпеку.

## Секрети
- Ніколи не пиши в код паролі, API-ключі, токени, приватні URL з ключами. Тільки env-змінні.
- Не комітити `.env`, ключі, дампи БД. Перевір `.gitignore`.
- На фронтенді немає секретів: усе, що потрапляє в браузер (включно з `NEXT_PUBLIC_*`, `VITE_*`), — публічне.

## Фронтенд (React / Vue / HTML)
- Не вставляти неперевірений HTML: без `dangerouslySetInnerHTML`, `v-html`, `innerHTML` з даними користувача/API. Якщо без цього ніяк — тільки після санітизації (DOMPurify).
- Посилання з даних: дозволяти тільки `http(s):` / `mailto:` / `tel:`, ніколи `javascript:`.
- `target="_blank"` → разом з `rel="noopener noreferrer"`.
- Не зберігати токени сесії в `localStorage`, якщо проєкт уже використовує httpOnly cookies.
- Сторонні скрипти (трекери, віджети) — тільки з довірених джерел, через механізм проєкту (наприклад, `next/script`), з `integrity` для CDN, якщо можливо.
- Форми: валідація на клієнті — для зручності, але НЕ замість серверної.

## Бекенд (Node / PHP / Python)
- Вхідні дані: валідувати тип, довжину, формат на сервері (zod/joi/yup, Laravel validation, pydantic).
- БД: тільки параметризовані запити / ORM. Ніколи не склеювати SQL з рядків вводу.
- Команди ОС: не передавати ввід у `exec`/`shell_exec`/`subprocess(..., shell=True)`.
- Файли: перевіряти тип і розмір при завантаженні, не довіряти імені файлу, не дозволяти `../` у шляхах.
- Авторизація: перевіряти права на сервері для кожного запиту до чужих даних (не лише «чи залогінений», а «чи це його ресурс»).
- Помилки: користувачу — загальне повідомлення, деталі — тільки в лог. Без персональних даних і токенів у логах.
- CORS: не ставити `*` для ендпоінтів з авторизацією.
- Залежності: не додавати нові пакети без потреби; якщо додаєш — популярні, підтримувані, без відомих вразливостей (`npm audit` / `composer audit` / `pip-audit`, якщо доступно).

## Персональні дані й оплата
- Будь-які зміни в оплаті, авторизації, реєстрації, персональних даних — роби особливо обережно: поясни людині ризик простими словами, проганяй усі наявні тести, і перед публікацією отримай окреме явне «так» саме на цю частину.
- Не логувати й не відправляти в аналітику email, телефон, дані карток.

## Перевір перед завершенням
- `git diff` не містить секретів (пошукай `key`, `secret`, `token`, `password`, довгі випадкові рядки).
- Немає нового неекранованого виводу HTML і склеєних SQL-запитів.
